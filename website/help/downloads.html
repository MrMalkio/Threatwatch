How download containment works

Threatwatch tries to stop common download attempts before Chrome keeps a completed file, then uses the downloads API as a fallback for attempts that get past the early layers.

Layer 1: page interception

On Strict and Learn profiles, a MAIN-world guard runs at document_start. It can stop download anchors, programmatic anchor clicks, risky form submissions, save pickers, existing file-handle writes, legacy save APIs, and risky targets passed to window.open().

Layer 2: network rules

Threatwatch uses Chrome Declarative Net Request rules to reject known risky filename extensions and selected response-header patterns, including forced attachments and dangerous executable MIME types.

Layer 3: download-manager fallback

If Chrome still creates a download item from a protected Strict or Learn context, Threatwatch attempts to pause and cancel it at the earliest download-manager events Chrome exposes. It can retry attribution during filename determination and make best-effort attempts to remove a file that won a race to completion.

Why Norton or another endpoint product might still alert: endpoint security can observe network traffic, browser file creation, or operating-system activity outside the extension's control. Threatwatch cannot promise it will always act first.

What gets treated as risky early

The rule set includes common executable, installer, script, browser-extension, archive, disk-image, application package, macro-enabled Office, and related filename extensions. Encoded filename separators are covered where Chrome's network rule engine can match them.

Testing safely

Use harmless files and a local test server. Do not download live malware to prove the extension works. Security testing against a third-party service without authorization can create legal and operational problems.

If a download was blocked but you wanted it

Do not disable the whole profile. Confirm the source and destination independently, use a trusted official source when possible, and prefer a narrow temporary exception once Threatwatch ships that workflow. Current 0.4.0 users should leave the protection in place rather than casually weakening the site profile.
