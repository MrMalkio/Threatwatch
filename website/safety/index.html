Threatwatch / Safety
Safety model

Harm reduction without pretending the browser can make bad sites trustworthy

Threatwatch focuses on streaming-site browser abuse. It is deliberately narrower than a full security suite and deliberately avoids calling a domain safe just because a user got playback.

Product boundary

What Threatwatch is built to do

  • Contain selected redirects, popunders, protocol launches, download attempts, suspicious clipboard writes, fake verification patterns, overlays, and abusive permissions.
  • Keep a local record of interventions with sanitized URLs.
  • Let users create per-domain protection profiles.
  • Help users distinguish a working site from a lower-risk site.
  • Remain useful with no account and no Threatwatch backend.
Outside the boundary

What Threatwatch will not promise

  • Guaranteed malware detection or prevention.
  • Legal, licensing, ownership, or copyright verification for third-party content.
  • Protection from browser zero-days, malicious extensions, endpoint malware, DNS compromise, or attacks outside Chrome.
  • A ranked directory of replacement piracy domains.
  • A finding that a domain is safe, clean, virus-free, or official.
Future reputation language

Use evidence labels, not green-check theater

Availability

Does the domain load and does playback appear to work?

Experience

Was the session usable, mixed, bad, or unusable?

Observed risk

What redirects, downloads, ClickFix attempts, overlays, or other threats appeared?

Evidence confidence

How much credible use supports the report?

Rule of thumb: if the only way to make a site work is to disable multiple security controls, run shell commands, install an unknown extension, allow notification spam, or download a mystery player, leave the site.

Responsible testing

Test Threatwatch with harmless fixtures and disposable browser profiles. Do not collect live malware, probe third-party systems without authorization, or publish exploit details that could put users at risk.

Community reports

Future reports should describe observed browser behavior rather than accuse named individuals. Domain relationships, mirror claims, and operator identity should be treated as claims carrying evidence and confidence.

Security reports about Threatwatch

If you discover an exploitable bug in Threatwatch, avoid posting working exploit steps publicly. Use GitHub's private security reporting path when available. See the repository Security page.
